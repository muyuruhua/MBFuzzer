MBFuzzer 与 mbfuzzer_artifact 综合分析

一、总体原理
MBFuzzer 是一个面向 MQTT broker 的黑盒多方差分模糊测试器。它的目标不是只测单一客户端到 broker 的两方交互，而是把 publisher、subscriber 和 broker 的多方通信纳入测试空间，通过构造带有协议依赖关系的消息序列，同时驱动多个 broker 实例参与同一轮测试，再比较各 broker 的响应差异，从而发现内存漏洞与非合规漏洞。

mbfuzzer_artifact 是在 MBFuzzer_Artifact 基础上的扩展版本。其核心思路不是改写原始实现，而是在外层增加新的入口、运行时扩展层、并行编排脚本以及 gcov 覆盖率采集与汇总逻辑。原始 fuzzing 与差分检测链路仍然保留。

二、工作流程
1. 初始化运行环境
- 创建输出目录、crash/queue/diff/valid_conn 等子目录。
- 启动缓存 broker 和 MQTT broker 代理。
- 等待所有预设 broker 的 bridge 状态建立完成。
- 进入 fuzzing 主循环。

2. 生成测试消息
- 根据协议语义和消息依赖规则决定下一条消息类型。
- 结合依赖队列协调两个发送端的消息顺序。
- 使用消息优先级调度器（Q-learning）动态决定更值得探索的消息类型。
- 按协议字段范围生成合法结构，再进行字段级变异。

3. 发送与收集
- 同一轮测试消息会并发发送到多个 broker。
- 每个 broker 的响应会被分别记录。
- 转发消息与普通响应分开处理，以避免 MQTT 订阅场景下的误报。

4. 差分分析
- 对不同 broker 的响应做两两比较。
- 先按消息结构与字段进行解析，再判断字段是否缺失、额外出现或取值不同。
- 对转发消息先进行 topic/payload 对齐，减少网络乱序带来的假阳性。

5. 结果反馈与落盘
- 发现新的不一致后，将相关输入保存为差分种子。
- 差分结果反向作为反馈，驱动后续消息优先级调整。
- 崩溃输入保存为 crash 结果，差分输入保存为 diff 结果。
- fuzz 结束后生成报告；扩展版本还会输出 paper_metrics.json 和 coverage 相关文件。

三、核心数据流
协议规范 / 依赖规则
  -> 消息类型选择
  -> 依赖队列 / 优先级调度
  -> 消息生成与变异
  -> 并发发送到多个 broker
  -> 收集响应与转发消息
  -> 解析为字段级结构
  -> 两两差分比较
  -> 生成差分结果或崩溃结果
  -> 反馈给调度器与语料库
  -> 报告与人工/LLM 复核

四、核心思想
1. 扩大输入空间
MBFuzzer 通过多方通信模型，而不是传统两方 fuzzing，覆盖 broker 在多角色、多实体协作场景下的逻辑路径。

2. 把协议依赖转化为测试约束
六条依赖规则和依赖队列确保消息发送顺序与字段组合符合协议语义，从而让测试资源集中在更有可能触发问题的路径上。

3. 以差异作为反馈信号
不同实现之间的响应不一致被视为重要反馈信号，用于提示潜在的规范偏离或逻辑错误。

4. 用学习型策略提高效率
Q-learning 根据历史发现的差异动态调整消息优先级，提高漏洞发现效率。

5. 结合事后复核降低误报
论文引入 LLM-based non-compliance bug analyzer，对差分结果进行自动验证，判断是否确实违反 MQTT 规范。

五、MBFuzzer 如何发现漏洞
1. 内存漏洞
- 通过变异后的非法或边界消息触发解析异常、状态机错误或崩溃。
- 典型表现是进程崩溃、连接断开、异常退出码或 crash 记录。

2. 非合规漏洞
- 同一个输入在不同 broker 上产生不同响应。
- 可能表现为响应缺失、额外响应、字段值异常、转发行为不一致或状态机行为不一致。
- 这些不一致被差分 checker 标记，再由 LLM 工具或人工复核是否真的违反协议规范。

3. 为什么多 broker 差分有效
- MQTT broker 的关键 bug 往往出现在消息路由、订阅转发、桥接、协议边界和状态同步等多方交互逻辑中。
- 多 broker 差分可以暴露“实现之间的不一致”，这是单目标 fuzz 很难直接覆盖到的。

六、mbfuzzer_artifact 相对原始版本的扩展
- 新增 gcov 入口与扩展层，而不是修改原始核心文件。
- 新增并行脚本，支持多个 worker 并行跑实验。
- 新增 Docker 侧的 gcov flush daemon 和 entrypoint，用于崩溃后尽量保留覆盖率数据。
- 新增后处理脚本与 paper_metrics 输出，使实验结果更适合论文整理与复现实验。

七、结论
MBFuzzer 的本质是“多方消息依赖驱动的黑盒差分 fuzzing”。它通过多 broker 并发通信、差分比较、优先级调度和事后复核的组合，既能发现崩溃类内存漏洞，也能发现实现与 MQTT 规范不一致的非合规漏洞。

mbfuzzer_artifact 在此基础上主要做了工程化增强：保留原始 MBFuzzer 的发现机制，同时增加覆盖率采集、并行化和实验报告能力。
